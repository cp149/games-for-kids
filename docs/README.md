# Project Documentation

This directory contains all project documentation managed by the **@project-chronicler** agent.

## Directory Structure

```
docs/
├── development-logs/          # Daily/weekly development progress
├── lessons-learned/           # Retrospectives and insights
│   ├── success-stories/      # What worked well
│   └── mistakes-and-fixes/   # What didn't work and how we fixed it
├── architecture/             # System design and architecture
│   ├── decisions/           # Architecture Decision Records (ADRs)
│   └── diagrams/            # Architecture diagrams
├── best-practices/          # Team guidelines and standards
├── troubleshooting/         # Common issues and solutions
└── knowledge-base/          # Reference materials and guides
```

## How to Use

### For Team Members

1. **Check development logs** for recent progress and updates
2. **Review lessons learned** before starting similar work
3. **Consult troubleshooting** when you encounter issues
4. **Reference best practices** when writing code or making decisions
5. **Read architecture decisions** to understand why things are the way they are

### For @project-chronicler Agent

Use the templates in each directory to document:
- Daily/weekly progress
- Major decisions
- Lessons learned
- Common issues and solutions
- Best practices discovered

## Quick Start

### Document a New Feature
```
@project-chronicler Document the implementation of [feature name]
```

### Record a Lesson Learned
```
@project-chronicler We just discovered that [lesson], please document this
```

### Create Weekly Summary
```
@project-chronicler Create a summary of this week's development progress
```

### Record an Architecture Decision
```
@project-chronicler Document the decision to use [technology/pattern] and why
```

## Documentation Standards

- **Be Specific**: Include code examples, file references, and metrics
- **Explain Why**: Focus on rationale and context, not just what was done
- **Keep Current**: Update docs when things change
- **Make Searchable**: Use clear titles and consistent tags
- **Be Actionable**: Include concrete takeaways and next steps

## Regular Activities

- **Daily**: Quick development log entry (optional)
- **Weekly**: Compile weekly summary and review lessons
- **After Major Features**: Document implementation and learnings
- **After Bugs**: Record the issue and solution
- **After Decisions**: Create ADR for significant choices
- **Monthly**: Review and organize documentation

## Need Help?

Ask **@project-chronicler**:
- "How should I document this?"
- "Create a template for [type of documentation]"
- "Summarize our recent progress"
- "What have we learned about [topic]?"
